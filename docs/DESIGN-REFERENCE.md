## 一個關鍵發現：它跟幾分是同一個色系家族

DESCENT 的色票不是「電競深色」，而是一套 **paper（紙）／ink（墨）／gold（金）** 的語意系統——
**這正是幾分現有的視覺語言，只是把明暗反過來。**

| 角色 | DESCENT | 幾分現況 | 差異 |
|---|---|---|---|
| 紙／底 | `paper #F6EAD2` | `bg-light #FBF8F3`／`bg-base #F4EFE7` | 幾乎同一個奶油色，DESCENT 略暖、彩度高一點 |
| 墨／主文字 | `ink #1D1626` | `text-primary #2C2926` | 同為近黑，但 DESCENT 帶**紫調**，幾分帶**棕調** |
| 金 | `gold #F2C14E` | `gold #EBA63E` | 極接近，DESCENT 略亮 |
| 青 | `teal #5FC9C4` | `teal #46C2A6` | 極接近，DESCENT 偏 cyan |
| 暖紅 | `red #E0574C` | `rose #E8628A`／`berry #C0396B` | 幾分偏粉紅，DESCENT 偏磚紅 |

**結論：採用這個參考不需要放棄幾分的識別，它是同一套語言的「夜間版」。**

## 字體處理（HUD 顯示字）

從 bundle 取到的實際參數：

```js
{ size: 16, weight: 0.17, fill: gold, ink: ink, tracking: 0.22, skew: <slant>, inkWidth: 0.062 }
```

翻成可執行的規則：
- **全大寫**、**字距極寬**（tracking ≈ 0.22em）——載入畫面的 `SHAPING THE MASSIF` 就是這個處理
- **輕微傾斜**（skew ≈ 0.17）製造速度感
- **深色描邊**（inkWidth ≈ 0.062×字級）讓亮字壓在任何背景上都清楚
- 數字用**金色填色 + 墨色描邊**

## 面板構造

- 深墨底 + **細亮邊**，四角**切角／缺口**（非圓角）——工業儀表感
- 排名列左側有一條**色塊指示條**（領先＝亮色、自己＝金色高亮）
- 大量**細分隔線與刻度**（速度表、進度軸），資訊密度高但層級清楚
- 標籤字極小且靜音色，數值極大且高對比——**標籤與數值的對比極端**

## 該學什麼 ✅

1. **語意化 token 系統**（最有價值）
   DESCENT 用 `ink / paper / gold / teal` 這種角色命名，不是 `purple-700`。
   幾分**現在的技術債正好是這個**——`globals.css` 定義了 token 但元件幾乎全部硬寫 hex（見 PRODUCT.md 視覺語言段的警告）。
   導入這套參考正好是**還掉那筆債的好理由**：先建立語意 token，再讓元件真正消費它。

2. **標籤／數值的極端對比** —— 幾分的結果頁（分數、百分位、樣本數）很適合這種處理。

3. **描邊顯示字** —— 讓大數字在任何底色上都立得住。

4. **高資訊密度的儀表構造** —— 幾分的 `RingGauge` + `DataBar` 已經是同一個方向，可以再精緻化（刻度、細分隔線）。

## 不該學什麼 ⚠️

**排名階梯（`1 MAGS LEAD / 2 OKOYE +0.8 / 3 YOU +6.1`）不要照搬。**

那是賽車遊戲的核心機制，但幾分的 [Non-goals](./PRODUCT.md#明確不做的事non-goals) 明確排除**公開排行榜**，理由是「排行榜必然製造墊底者」，與「不讓人自卑」的初衷直接衝突。一個外貌評分服務如果長得像即時競速排名，會把產品推向它刻意要避開的那一面。

**建議：學它的材質，不學它的競爭框架。**
